# 用户认证与权限

首版在现有工作台内实现本地账号，不需要额外部署“权限管理平台”。`/login`、`/register` 负责用户入口；仅平台管理员能访问 `/admin/users`，在此审核申请、调整角色或停用账号。角色是固定的三档，不开放逐接口自定义授权，避免权限组合失控。未来需要企业统一登录时可把认证入口替换为 OIDC，业务授权仍由 Go 控制面执行。

## 权限矩阵

| 角色 | 可使用的业务区域 | 账号管理 |
|---|---|---|
| 平台管理员 | 全部，包括标注成果的数据集版本发布 | 审核、修改角色、停用账号 |
| 标注员 | AI 标注工作区、人工复核队列；读取完成标注所需的数据集、模型和策略上下文 | 无 |
| 业务人员 | 工作台、数据集、训练、推理、权重、人工复核、反馈池、模型、流水线、硬件监控；不进入 AI 标注区 | 无 |

标注员可以提交确认结果、编制发布预览，但将标注或反馈正式注册为新数据集版本需要管理员确认。前端隐藏无权限导航、阻止直接访问对应路由；**真正的授权在 Go API**，直接调用接口同样会得到 403。用户角色或状态变更会撤销该账号全部旧会话；最后一位有效管理员不能被停用或降权，管理员也不能在界面修改自己的角色或状态。

## 首次初始化与日常操作

1. 运行现有 Alembic 迁移：`docker compose run --rm --no-deps migrate`（若用 `scripts/demo-up.sh` 启动，迁移由启动流程执行）。
2. 创建首位管理员：`docker compose run --rm --no-deps --entrypoint /usr/local/bin/finevision-admin go-control-plane --email admin@example.com --name 平台管理员`。密码在终端提示时输入，长度 12–1024 字节。该命令重复执行会重置同一邮箱的管理员密码并撤销旧会话，不能用于常规用户管理。
3. 用户打开 `/register` 填写邮箱、姓名与密码。新账号始终为“待审核”，默认业务角色只是数据库初始值，**不能因此登录**。
4. 管理员打开 `/admin/users`，可按姓名、邮箱和状态定位用户；选择“标注员”或“业务人员”，将状态改为“已启用”，填写变更原因后保存。管理员也可将账号设为“已停用”。变更进入 `app_user_events` 审计表。

不支持公开注册成为管理员。增加其他管理员时，由现有管理员在用户管理页将已注册账号设为管理员并启用。平台管理员应使用独立账号，不共享密码。

## 安全边界

- 密码只存 Argon2id 哈希（19 MiB、2 次迭代、单并行度及随机盐），不进入响应或日志。单账号连续失败 5 次临时锁定 15 分钟；服务端对注册、登录请求体限制为 4 KiB。
- 会话令牌使用 256 位随机数；数据库只存其 SHA-256，默认 12 小时后失效。Cookie 为 HttpOnly、SameSite=Lax；非 `FINEVISION_ENVIRONMENT=local` 环境还设置 Secure 与 `__Host-` 前缀，必须通过 HTTPS 访问。所有状态修改请求还要提交会话关联的 `X-CSRF-Token`。
- Go 控制面执行角色授权；标注 Worker、部署 Worker 等内部回调继续使用独立的 Bearer 服务令牌，不能拿用户 Cookie 代替。`/api/health` 可匿名访问，Prometheus `/metrics` 沿用原有观测网络边界；公网应进一步限制这两个入口。
- 本地账号适合当前三角色和单组织。邮箱所有权验证、密码找回、MFA、外部账号生命周期及 OIDC/SSO **本期尚未实现**；管理员应通过其他可信渠道核实申请人身份，不能仅凭填写的邮箱批准。不能把本地登录当作公网生产环境的完整安全方案。生产使用前至少配置 TLS、同源反向代理、登录及注册限流、数据库备份、日志保留和服务令牌管理。

API 契约参见 `/swagger/` 中的“用户与权限”分组，以及 [auth.yaml](../go/api/openapi/auth.yaml)。
