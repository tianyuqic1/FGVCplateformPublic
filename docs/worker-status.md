# Worker 状态与独立部署

入口 `/workers`，管理员与业务人员只读访问。标注员不可访问此页面及接口。此页不提供容器重启、停止、排队调度或日志全文。

## 角色视图与任务归属

- 管理员：完整实例诊断、启动会话、心跳序号及全部关联任务，技术信息直接展开。
- 业务人员：共享服务可用性、总负载与本人训练任务。技术信息默认折叠；服务端不返回启动会话、心跳序号、原始异常说明、其他人的任务 ID。页面显示的是平台总负载，不能把它称作“我的任务数”。
- 标注员：仅标注页显示 AI 服务已就绪、已连接、初始化、不可用或状态未确认，以及可继续人工标注的说明。`/api/annotation/status` 不再返回实例参数和当前任务 ID。

新训练任务的 `jobs.payload.created_by_user_id` 由服务端从登录会话写入，不接受客户端指定。Worker 查询在控制面数据库核实归属，不相信 Worker 自报所有者。历史任务无归属不补猜，业务人员不可从 Worker 接口看到这些任务详情；推理、标注、导出请求暂无完整所有者关联，也只计入共享负载。归属查询失败返回错误，不回退到全部任务。

这是一层 **Worker 视图的数据最小化**，并非全平台多租户隔离：现有训练、数据集等页面仍遵循原平台级角色权限。后续如需私有项目，必须另行统一所有业务 API 的资源授权。

## 接入范围

- 训练消费者：空闲心跳，任务执行时关联训练运行 ID，进度和结果仍以训练详情为准。
- 推理运行时：正在处理的 RPC 数量与线程池容量；健康探测不计为推理任务。不把请求 ID 当作模型 ID。
- 数据校验 / 导出运行时：正在执行的 RPC 方法及请求 ID。
- TensorRT / Ascend 构建消费者：消费状态、构建执行情况。
- AI 标注 Worker：工作流或人工确认样本入库任务；保留原有标注页心跳兼容接口。

暂不采集实例级显存、推理延迟分布、已加载模型列表，也不独立探测所有依赖。GPU 指标仍属于节点整体，不能归属到单个 Worker。没有接入登记的进程不会出现，空列表不代表没有服务运行。

## 配置

| 变量 | 说明 |
| --- | --- |
| `FINEVISION_CONTROL_PLANE_HTTP` | Worker 可访问的控制面 HTTP 地址，不能填写其他机器上的 localhost |
| `FINEVISION_WORKER_TOKEN` | 控制面与 Worker 一致的专用上报令牌；未配置时不上报，不影响业务任务 |
| `FINEVISION_WORKER_ID` | 建议设置稳定且唯一的实例名，如 `training-gpu-a-01`；同一 ID 新会话将替代旧会话 |
| `FINEVISION_WORKER_NAME` | 页面展示名 |
| `FINEVISION_NODE_ID` | 与硬件采集器一致才可关联计算资源；不能给远程节点沿用本地节点 ID |
| `FINEVISION_SERVICE_VERSION` | 发布版本或构建 commit |
| `FINEVISION_COMPUTE_DEVICE` | 实际配置的计算设备；不可只为美化页面填写 |

Compose 的开发令牌只用于本地环境，生产部署必须覆盖为独立随机凭据，使用私网和 TLS。该令牌只能写观察数据，不等于用户登录或任务租约凭据。多副本不能使用同一 Worker ID。默认 ID 为服务类型 + 主机名；容器替换改变主机名会产生新的历史实例。

运行迁移 `alembic upgrade head`（新增 `20260926_0024`），更新控制面，再更新各 Worker。正在运行任务时先等待完成再重启。原有任务队列、生命周期 RPC 和租约续期保持不变。

本地标注启动脚本从控制面容器读取上报令牌，不写日志或命令行。旧进程需在无活动任务时重启才能启用新代码。

### 现有 Compose 部署升级

先确认长任务已完成，在项目根目录执行：

```bash
docker compose build migrate go-control-plane python-training-worker python-inference-runtime frontend
docker compose run --rm --no-deps migrate
docker compose up -d --no-deps go-control-plane python-training-worker python-inference-runtime python-artifact-runtime frontend
```

上述步骤假设 PostgreSQL、RabbitMQ、MinIO 等依赖已运行；GPU 部署必须沿用现有 GPU override，不能用 CPU 命令覆盖设备配置。独立标注和硬件构建 Worker 按各自部署方式更新。本功能的任务所有者保存在现有 `jobs.payload`，不需要额外所有者字段迁移。

### 跨主机通信与排查

`FINEVISION_CONTROL_PLANE_HTTP` 只负责状态登记和心跳，不能替代原有控制面 gRPC、RabbitMQ、MinIO 或推理 RPC 地址。跨主机应逐项配置这些地址与网络访问规则；优先采用私网、VPN 或受控 TLS 入口，不直接向公网暴露数据库和消息队列。Compose 内的 `http://go-control-plane:8000` 仅在对应容器网络可达。

- 实例未出现：检查进程是否接入 Reporter、令牌是否配置、地址和网络是否可达。
- 上报 401/403：核对控制面与 Worker 的专用令牌，修正后重启空闲实例。
- 上报 409：检查重复实例 ID 或旧启动会话；不能盲目重新登记以抢回身份。
- 在线但任务失败：查训练/推理详情与独立日志控制台；心跳在线不等于所有依赖健康。

Swagger 的“Worker 状态”分组及 [workers.yaml](../go/api/openapi/workers.yaml) 描述读取与内部上报接口；Swagger 本身仅管理员可访问，业务人员使用工作台即可。

## 一致性与含义

1. 每次启动生成新的 session UUID，通过登记接口创建启动会话；旧会话记录保留，避免迟到的重复登记夺回实例。
2. 心跳约每 10 秒独立发送，采用单调递增序号；旧会话或重复序号返回 409。收到 401/403/409 停止遥测，不中断业务任务，也不反复创建会话。
3. 使用数据库接收时间判断新鲜度，不依赖 Worker 时钟。30 秒以内在线，超过 30 秒延迟，超过 90 秒失联；主动结束可上报 stopped。
4. 在线不等于依赖全部健康。就绪仅代表本进程已进入服务阶段；当前实际观察到的依赖错误会显示原因。未探测的依赖不显示“通过”。
5. 可接任务 = 在线 + ready + 当前执行数小于并发上限。属于观察结果，不是调度授权。
6. 失联后的任务和负载保留为最后观测，不据此重试、取消或迁移任务。模型与训练的最终状态仍由原业务控制面决定。

列表接口 `/api/workers` 支持 q/kind/status/device、limit/offset；汇总基于全部筛选结果，不基于当前页。详情 `/api/workers/{id}` 可直达。API 错误显示读取失败，不伪装成全部离线或零实例。

上报结构只接收限定字段、32 KiB 以内载荷，不含环境变量、认证信息、连接字符串、图片或原始异常全文。保留历史实例与会话用于诊断，首版无删除入口。
