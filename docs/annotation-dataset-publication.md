# 标注发布与推理回流

## 最终边界

已注册数据集版本的标签视为正确，**不提供标签修改、替换图片、删除历史样本**。本期只追加新样本。

“补充原版本的训练集”是操作语义；实现时保留原版本，创建以它为父版本的新快照。每个数据集单独递增版本号。用户可以明确选择旧版本作为基准；例如已有 v2，再基于 v1 发布，得到 v3（parent=v1），不会隐式包含 v2 的独有图片。界面显示基准版本，混合来源反馈有警告。

## 使用入口

- `/annotation?tab=publish`：待发布区。
- `/annotation?tab=history`：发布记录。
- 反馈池的「回流待发布区」：`/annotation?tab=publish&source=feedback`。
- 发布完成后可查看数据集；满足既有 readiness 条件时可跳转创建训练。发布本身不启动训练。

## 两类来源与三种去向

| 来源 | 去向 | 划分规则 |
| --- | --- | --- |
| 人工确认标注 | 新建数据集 v1 | 用户自定训练/验证/测试整数百分比，默认 80/10/10 |
| 人工确认标注 | 追加已有数据集的指定版本 | 原样本划分保留；默认新样本全部进训练集，也可仅对新样本按比例划分 |
| 已复核推理反馈 | 原数据集的指定版本 | 新样本强制进入训练集；不允许发布到其他数据集或参与评估集分配 |

推理回流只接收已确认、目的地为 `training_candidate` 且尚未纳入版本的反馈。首张选择默认采用它的来源版本；整页选择且来源一致时也采用来源版本。OOD、坏图、不确定结果不作为训练候选。

本期不重新划分整个历史版本，不做历史标签修订。新建与追加都原样保留人工确认的类别名称：同名类别自动追加，不存在的类别只在新版本中新增。无需手动映射，名称不会被模糊匹配或由 AI 改写。检查清单显示已有类别的新增张数和新增类别名称/张数；同图异标签仍阻断整批。旧版本类别和标签不变。包含旧式手动映射的未发布批次需取消后重新检查。

## 划分和检查

1. 训练比例大于 0；验证/测试可为 0；三者总和必须为 100。
2. 每类按 `SHA256(seed:source_sha)` 排序，用最大余数法分配样本，至少保留一个训练样本。上传顺序不影响结果；默认 seed=42。
3. 少样本类别无法覆盖指定集合时给出提示，并展示各类三个集合的实际数量。最终能否训练仍由数据扫描 readiness 判断。
4. 相同文件 SHA 同标签去重。与已有标签冲突则阻断整批，**不会通过改旧标签解决**。
5. 已属于基准验证/测试集的相同图片禁止再加入，防止回流污染评估集。
6. 历史图片字节、标签、划分全部保留；新版本有自己的样本 ID 和 manifest，不覆盖旧文件。
7. 当前是文件 SHA 精确去重，不承诺识别重新编码、近似图片、同一拍摄对象或连续帧；这类数据应在采集阶段按组隔离。本期未引入感知哈希/近重复检索。

单次最多选 1000 张；待发布样本、发布记录每页 12 条，可跨页选择。标注来源使用数据库 LIMIT/OFFSET；反馈来源复用已有上限 10000 条的候选仓库，并按批次占用过滤后分页。目标下拉支持搜索/分页，目前最多返回 2000 个版本。原有数据集总上限仍是 100000 张、5 GiB，单图片受既有上限约束。

## 发布批次与恢复

用户点击「检查发布清单」后：读取权威人工标签 → 校验/去重 → 构造显式 split ZIP → 校验后存入 MinIO → 保存预览批次。此时不注册数据版本、不运行训练/LLM。单控制面只允许一个清单构建同时进行，最长 20 分钟。

点击「确认发布」时，在事务内占用来源记录并进入后台队列。一个来源记录只能被一个有效批次占用，防止同一标注或反馈重复发布。后续新确认的样本进入下一批，不进入已冻结 ZIP。

状态：`preview → queued → building → registering → published`，失败进入 `failed`。

- PostgreSQL 保存批次、检查结果、对象描述符、所选来源及发布说明。
- 控制面后台单协调器使用 PostgreSQL session advisory lock，跨副本串行执行；不另起大模型或 GPU 服务。
- MinIO 再次检查 SHA/大小；Python 原有 scanner 检查图片并生成 manifest；Go 事务分配版本号、保存来源与 artifacts。
- 同一批次始终使用相同 dataset import request ID，注册后 ACK 丢失也可恢复，不重复创建版本。
- 崩溃释放 advisory lock，重启后恢复 `building/registering` 批次。普通失败保留占用和快照，人工点击「重试原批次」。
- `preview/failed` 可以取消；取消失败批次释放来源占用，便于重新选择目标或修改发布计划。运行中和已发布批次不可取消。
- 已发布记录不能再次添加到其他批次。该限制作用于标注任务/反馈记录；若需另做独立数据集，需显式建立独立导入/标注来源，不把同一确认任务反复消费。
- 原 ZIP、预览对象和发布记录保留审计；取消不删除对象。本期未做未引用预览对象自动 GC。

## API / 数据库

命名空间 `/api/annotation/publications`：

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| GET | `/targets` | 已有数据集版本、名称、类别和划分 |
| GET | `/candidates?source=annotation&scope=PROJECT&page=1` | 已确认未占用标注 |
| GET | `/candidates?source=feedback&scope=DATASET&page=1` | 可回流反馈 |
| POST | `/preview` | 冻结并检查清单，保存可恢复预览 |
| GET | `/?page=1` | 发布记录分页 |
| POST | `/{id}/publish` | 占用来源并排队，幂等 |
| POST | `/{id}/retry` | 重试同一失败批次 |
| POST | `/{id}/cancel` | 取消预览或失败批次 |

`preview` 请求包含 UUID `id`、`source`、`project_id`、`dataset_id/base_id` 或 `name`、`ids`、`train_only`、`split:{train,val,test,seed}`、`notes`。不接受非空 `mapping`（空值仅为旧客户端兼容）。请求 ID 相同但内容不同返回 409。

迁移：`20260914_0020` 添加批次/占用表；`20260914_0021` 增加 `annotation_publish/annotation_append` 来源枚举，不放松历史数据约束。新注册和反馈消耗继续复用原来的 `dataset_versions/artifacts/dataset_version_feedback` 事务链路。

仍按可信本地环境运行，尚未增加多人权限；不要将这些 API 直接暴露公网。备份应覆盖 PostgreSQL 与 MinIO。

- PostgreSQL 真实事务：幂等预览、改变请求 ID 内容被拒、同批重复发布、竞争批次占用冲突、失败重试、注册后丢失 ACK 恢复、旧基准连续发布分配 v2/v3、取消释放占用。
- 反馈回流通过真实元数据 fixture 检查：冻结图片后发布、仅增加训练集、消费标记、基于旧版本生成 v4、重放不重复消费。模型是测试元数据，不运行训练。
