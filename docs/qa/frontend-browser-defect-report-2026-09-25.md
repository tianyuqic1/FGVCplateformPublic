# FineVision 前端真实浏览器缺陷报告

测试日期：2026-09-25

测试版本：`f9802d76271642391f14ec2c5f3ad04efce2b9a7`

测试地址：`http://localhost:5173`

浏览器：Chromium（Codex In-app Browser）

视口：桌面 `1280 × 720`、移动端 `390 × 844`

## 1. 优先级定义

- **P0**：阻断全站或造成不可恢复的数据损坏，必须立即处理。
- **P1**：核心链路不可用、关键诊断缺失或页面给出错误业务含义，应进入最近一次修复。
- **P2**：局部可靠性、性能、可用性或扩展性问题，不阻断主链路但会持续增加使用成本。
- **P3**：视觉、文案、国际化或辅助功能问题，可随页面迭代处理。

## 2. 测试结论

更新前端容器后，主要只读页面均可稳定打开，未发现浏览器控制台错误，也未发现整页横向溢出。以下链路已通过真实浏览器操作：

- 首页作用域、风险队列与发布检查加载正常。
- 数据集列表真实返回 25 个数据集；每页 6 个，翻页和名称搜索正常。
- CUB-200 数据集详情的 6 张样本图均成功加载。
- 训练列表状态筛选正常，可定位 3 个失败运行。
- 复核队列显示真实总数 1477；第 2 页正确显示 7–12 条，详情图像和 top-k 证据正常。
- 模型详情展示已发布的 ONNX FP32、FP16 与 TensorRT 部署记录。
- 硬件监控、权重、流水线、反馈池和 AI 标注页面均可打开。
- 移动端主要页面没有整页横向溢出。
- 使用 CUB 样本 `sample-6d5340612201` 实际执行 ONNX Runtime CPU FP32 推理成功，服务记录耗时 `8016 ms`，结果触发弃权并生成复核项 `review-7732f11e-2cae-4a9e-aaaa-04a2148b43b2`。本次测试没有提交人工结论，因此没有写入反馈池。

## 3. 缺陷清单

### QA-001 · P0 · 前端容器依赖漂移会导致全站白屏

**现象**

浏览器打开首页只有空白页，`#root` 没有挂载内容。Vite 返回：

```text
Failed to resolve import "@tanstack/react-query" from "src/main.jsx"
```

**复现条件**

1. 前端容器已运行。
2. 宿主机源码通过 volume 挂载到 `/app/src`。
3. `package.json` 增加依赖，但容器仍保留旧镜像中的 `node_modules`。
4. 刷新 `http://localhost:5173/`。

**原因判断**

Compose 只挂载 `src`、`scripts` 和 `index.html`，依赖来自构建镜像。源码可以热更新，但依赖不会同步，形成“新源码 + 旧 node_modules”的不一致状态。当前健康判断只证明端口在线，不能证明入口模块可编译。

**临时处理**

本次通过重新执行 `docker compose build frontend && docker compose up -d frontend` 恢复。

**建议修复**

1. 增加开发/生产两个 Compose profile；生产使用不可变构建产物，开发环境使用依赖哈希或显式 `npm ci`。
2. 为前端增加能够校验入口脚本的 healthcheck，而不是只检查 5173 端口。
3. 启动脚本检测 `package-lock.json` 与镜像标签是否一致，不一致时直接失败并给出重建命令。

### QA-002 · P1 · 失败训练详情没有展示 API 已返回的错误与 Job ID

**现象**

失败运行 `fc4af939-1bca-4b3c-9d58-2f20f66161bd` 的详情只显示“失败”和缺失产物，没有失败原因和任务 ID。

API 实际已经返回：

```text
job_id: 0914c25c-cb1c-46d1-8370-3db4fdfcb3aa
error: [Errno 13] Permission denied: '/data/work/features'
```

`normalizeTrainingRun` 也保留了 `jobId` 和 `error`，缺失发生在详情页面渲染层。

**影响**

用户无法从 UI 定位 worker 任务，也无法判断失败发生在权限、数据、显存还是模型阶段，只能查看 API 或日志。

**建议修复**

在失败/取消状态顶部增加“运行诊断”面板，至少展示 `error`、`jobId`、`attemptId`、`runtimeNodeId`、开始/结束时间和缺失产物，并提供复制技术信息按钮。

### QA-003 · P1 · 全局搜索并不搜索真实数据集或复核记录

**现象**

顶栏占位符写的是“搜索页面、数据集、复核历史”，但搜索 `CUB-200` 时返回“没有匹配项”，即使当前首页和数据集列表都存在 CUB-200。

**原因判断**

搜索数据来自 `AppShell.jsx` 中的静态 `searchItems`，只覆盖少量固定路由和一个固定 CIFAR10 条目，没有连接数据集、训练运行、模型版本或复核接口。

**影响**

搜索框对外承诺了业务实体检索，但实际只是静态导航，会让用户误判数据不存在。

**建议修复**

短期将占位符改为“搜索功能页面”，避免错误承诺；随后增加统一搜索接口或按需并行检索数据集、训练运行、模型版本与复核编号，并对结果标注实体类型。

---

### QA-004 · P1 · 权重页训练方式文案与当前训练实现冲突

**现象**

训练页明确说明：DINOv3 冻结骨干并可选 LoRA，ImageNet 权重进行全量参数更新；但权重管理页仍把 DINOv3、ImageNet ViT-S 和 ResNet-50 描述为“冻结特征提取后训练轻量分类头”。

**影响**

同一平台对训练策略给出互相冲突的解释，会直接影响用户选择骨干、估算显存和理解发布产物。

**建议修复**

权重目录只描述预训练来源、架构、SHA 和兼容训练策略；训练方式从后端 backbone capability/strategy schema 动态生成，避免复制业务规则到页面文案。

### QA-005 · P2 · 部分历史数据集的样本预览契约不完整

**现象**

`cifar10-mini` 的样本预览接口能返回样本和 `image_url`，但访问这些图片时连续返回 HTTP 422，页面只能显示“图片暂不可用”。CUB-200 的同一链路正常。

**影响**

旧数据集看起来已经注册且可训练，但样本证据不可审阅；返回一个随后不可访问的 URL 也会让前端无法区分“暂无图片”和“存储损坏”。

**建议修复**

迁移或补齐历史数据集的原图归档；预览接口增加 `image_available` 与不可用原因。若文件不存在，不应返回看似可用的图片 URL。

### QA-006 · P2 · 冷加载期间会短暂显示“0 个数据集 / 暂无数据集”

**现象**

路由组件加载完成、业务请求尚未返回时，数据集页同时显示“正在读取数据资产”“共 0 个数据集”和“暂无数据集”。约 1 秒后才变为真实的 25 个数据集。

推理页也会在数据未返回时短暂显示“暂无训练数据集 / 暂无已发布模型”。

**影响**

慢网络或远程部署下，用户会把加载过程误认为真实空状态。

**建议修复**

把 `loading`、`empty` 和 `error` 设为互斥状态；加载阶段使用骨架屏或“正在同步”，只有成功返回空数组后才显示空状态。

---

### QA-007 · P2 · 单张 CPU 推理缺少可取消操作与阶段进度

**现象**

本次单张 ONNX CPU FP32 推理耗时约 8.0 秒。运行期间页面只显示“正在运行推理”和泛化进度文案，不能取消，也看不到图片读取、RPC、模型执行或证据写入阶段。

**影响**

首次模型加载、低资源部署或服务异常时，用户无法区分“正常较慢”和“请求卡死”。

**建议修复**

前端请求接入 `AbortController`；后端返回阶段或至少服务端超时预算。展示“准备输入 / 模型执行 / 写入事件 / 创建复核项”，并在超时后给出 request ID。

---

### QA-008 · P2 · 数据集、训练和模型列表仍是客户端分页

**现象**

页面虽然显示分页，但首次请求仍完整拉取列表：本次 `/api/datasets` 约 130 KB、`/api/model-versions` 约 118 KB、训练运行约 48 KB，再由浏览器过滤和切页。

**影响**

当前 20–30 条数据时可接受，但记录增长到数百或数千后，首屏时间、内存、重复刷新和移动端体验都会退化。

**建议修复**

后端统一支持 `limit`、`offset/cursor`、`total`、排序和筛选；React Query 的 key 包含分页及筛选参数，并使用 `placeholderData` 保留上一页，避免切页闪烁。

---

### QA-009 · P3 · 移动端导航只有图标且依赖横向滚动

**现象**

390 px 视口下没有整页横向溢出，但导航变成没有可见文字的图标条，并出现横向滚动条。首次使用者难以辨认图标含义，也不容易发现还有未显示入口。

**建议修复**

改为明确的菜单按钮或底部导航，保留当前页面文字标题；图标入口至少提供可见短标签或 Tooltip，并确保键盘焦点与屏幕阅读器顺序一致。

---

### QA-010 · P3 · 局部仍暴露英文原始值和缺失辅助名称

**现象**

- 复核详情描述中直接出现 `Model abstained for multiple threshold reasons.`。
- 训练列表失败指标显示原始 `failed`。
- 文件夹选择器显示浏览器原生 `Choose File/Choose Files`。
- 推理页的 Top-k 和近邻数在无障碍树中是没有名称的 spinbutton。

**建议修复**

建立统一状态与错误翻译层；为文件输入制作一致的可访问按钮；通过 `<label for>` 或 `aria-label` 为数值输入提供明确名称。

## 4. 建议修复顺序

1. **立即处理 QA-001**：避免任意依赖升级再次让整个本地站点白屏。
2. **同一批处理 QA-002、QA-003、QA-004**：分别修复诊断能力、搜索真实性和核心业务语义。
3. **随后处理 QA-005、QA-006、QA-007**：提高数据证据可靠性和长耗时操作体验。
4. **扩容前处理 QA-008**：把客户端分页迁移到服务端。
5. **视觉收尾处理 QA-009、QA-010**。

## 5. 回归验收建议

- 新镜像与旧容器组合下，依赖不一致必须明确失败，不允许白屏。
- 失败训练详情自动化断言 `error` 和 `jobId` 可见。
- 用 API 中真实存在的 CUB 数据集名称和复核编号验证全局搜索。
- 权重页策略文案由同一份 capability 数据生成。
- 对所有返回的 `image_url` 做可访问性契约测试。
- 使用延迟 2 秒的 API 测试加载态，确认不会提前显示空状态。
- 单张推理覆盖成功、弃权、OOD、超时、取消五种状态。
- 390 px、768 px、1280 px 三档视口加入 Playwright 截图与横向溢出断言。
