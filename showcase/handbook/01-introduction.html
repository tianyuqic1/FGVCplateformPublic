1. 项目介绍

1.1 一句话介绍

FineVision 是一个面向细粒度图像分类的可审计工程平台。它以数据集版本为坐标，把差异化训练、模型语义版本、完整推理部署、选择性弃权、人工复核、反馈闭环和 AI 辅助标注串成一条可追溯链路。

1.2 为什么要做这个项目

普通分类 Demo 只回答“这张图是什么”。真正可使用的平台还必须回答：训练输入是否可复现、权重是否完整、线上究竟运行了哪个后端、模型何时应该拒答、人工修正怎样进入下一版数据、长任务重试会不会重复写产物，以及模型生成的标注建议能否被审计。

DATA

数据可追溯

业务数据集、不可变版本、manifest、样本 SHA、split 与对象存储位置彼此分离，避免用路径或名称冒充身份。

TRAIN

训练可恢复

Go 负责任务、租约、代际和事件；Python Worker 负责 GPU 计算。暂停、恢复、取消和重复消息均有明确语义。

SERVE

发布可验证

训练完成不等于可以推理。发布需要生成完整 PT/ONNX，校验 SHA、大小和数值一致性，再注册部署产物。

HITL

决策可复核

置信度和 margin 触发弃权；人工结论进入反馈池，策略先 shadow 回放再人工激活。

ANNOTATE

标注有证据

VLM、主体定位、SAM、质量工具、CLIP/Qdrant 只负责提供候选与参考，最终标签属于人。

OPS

失败可解释

API、消息、执行 attempt、对象产物、远程调用和向量写入均保留故障位置与恢复动作。

1.3 产品目标

  • 以版本而不是文件夹管理数据：同一数据集的新增样本形成下一版本；已经注册的标签和 split 默认正确且不可变。
  • 以训练策略区分参数更新：DINOv3 冻结原始骨干，可选 QKV LoRA R8/R16；ImageNet 预训练分支执行骨干和分类头的全量更新。
  • 以发布门禁隔离训练和推理：候选模型必须显式发布，推理 Worker 只加载 production 且部署 ready 的完整模型。
  • 以风险而不是单一准确率组织线上决策：自动接受覆盖率与经验风险共同衡量，模型可以 abstain。
  • 以人工确认驱动持续数据闭环：复核、标注、向量记忆和数据版本发布都保留来源与幂等身份。

1.4 核心闭环

数据资产导入 / 标注发布Dataset + immutable Version
→
训练DINO LoRA / ImageNet FullJob + Attempt + Metrics
→
模型发布PT → ONNX / 部署格式SHA + size + parity
→
选择性推理accept / abstainEvent + policy snapshot
→
人工闭环复核 / 反馈 / 新版本Human truth + outbox

AI 标注是同一闭环的数据入口而不是独立产品：上传图片先绑定固定 JSON 类别目录，工作流生成 Top-10 候选，人完成确认；确认样本可进入检索记忆，也可按用户设置的 train/val/test 比例发布成新数据集或追加为已有数据集的新版本。
