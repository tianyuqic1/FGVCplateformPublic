3. 项目实现细节

3.1 架构总览

系统采用“Go 控制面 + Python 计算面”。CRUD、状态迁移、权限边界、幂等、发布协调和 LLM 接口由 Go 承担；训练、模型导出、特征编码、推理以及图像工具仍使用 Python 生态。训练 Worker 与推理 Runtime 分开部署，避免长时间训练占满在线推理进程。

3.2 为什么采用控制面 / 计算面拆分

问题控制面负责计算面负责收益
长任务超时创建 job、写 outbox、立即返回异步 claim 并上报心跳HTTP 生命周期不绑定 GPU 生命周期
重复消息检查 generation / epoch / attempt携带执行身份回调至少一次投递下仍能拒绝过期结果
大文件登记 descriptor、SHA、size、关系流式读写对象数据库不承载模型与数据二进制
运行时隔离选择可用 deployment按后端加载执行训练依赖与线上推理依赖可以独立演化

RabbitMQ 提供投递，不承担业务真相；PostgreSQL 中的 job/attempt 状态才是权威。MinIO 与数据库没有跨系统事务，因此对象先写入并校验，再在数据库事务中注册。数据库提交失败可能留下未引用对象，当前通过“从不把未登记对象视为有效资产”保持正确性，通用 GC 属于后续运维能力。

3.7 模型版本与发布门禁

训练 run、模型版本、发布版本和部署产物是四个不同实体。训练完成登记 candidate；发布计算语义版本并冻结源检查点；deployment 则描述同一 release 在某种后端、精度和硬件 profile 下的可执行物。

TrainingRun
  └─ Candidate Model
       └─ Release v1.0.0 (semantic identity)
            ├─ ONNX FP32 deployment
            ├─ ONNX FP16 deployment
            ├─ TensorRT plan (GPU profile bound)
            └─ Ascend artifact (SoC/CANN profile bound)

发布先深拷贝模型到 CPU/eval；DINO LoRA 将 W₀ + 2BA 合并为普通 Linear；再保存完整 PT 并导出 opset 17 ONNX。输出为 logits，batch 动态，H/W 固定。元数据保存类别顺序、归一化、输入尺寸、源模型版本、精度、SHA-256 和 size。随机 batch 1/2 数值探针用于发现转换错误，但不替代真实测试集验收。

版本规则不是“看起来指标更高就升 patch”。模型签名（架构、预训练来源、训练策略、输入契约等）变化升 major；数据集版本变化升 minor；同签名同数据的新训练产物升 patch。部署格式和精度只增加 deployment，不改变语义版本。

3.8 推理事件、校准与在线弃权

3.9 AI 标注编排与人工边界

标注不把 Eino 描述成万能 Agent。当前职责分工是：Python 编排器决定工具和阶段；Go LLM Gateway 用 Eino 封装 OpenAI-compatible 模型调用与结构化响应；本地多模态模型通过 llama.cpp GGUF 运行。模型只产生候选，Go 控制面校验目录和任务状态，人工确认才提交标签。

3.10 图像工具层与受限工作流

工作流采用“先观测、再选择、至多一个增强工具”。原图永远进入最终判断；主体视图只有通过边界与像素来源校验才可加入；低照度增强、去噪/清晰化或超分不会串联成不可解释的处理链。工具的目标是补证据，不是生成新的真值图像。

3.11 CLIP、Qdrant 与图文检索记忆

记忆仅接收人工确认且投递成功的样本。CLIP 图像分支把原图和可用主体图编码为 512 维单位向量；文本分支为类别名称构造三种领域模板原型。Qdrant 使用 cosine 距离，查询先在每个视图内按类别去重，再融合图像视图，最后与文本排名做 RRF，避免不同分数尺度直接相加。

3.12 标注发布与推理回流

已确认标注进入待发布区，可以创建新数据集，也可以追加到已有数据集。两种操作都生成新版本，绝不改写旧版本。用户设置 train/val/test 比例，系统按类别做确定性划分，先生成不可变 ZIP 和发布计划预览；提交时以稳定 request ID、advisory lock 和 publication member 唯一约束防止跨批次重复占用。

推理回流遵循相同规则，但只允许进入目标数据集下一版本的训练集：原数据版本保持不变，回流样本保留 inference event、人工确认和来源 member。这样既满足“回到原数据集”的产品语义，也不会破坏历史训练复现。

3.13 LLM 契约、结构化输出与密钥隔离

Browser
  → Go Control Plane (业务上下文、目录、授权范围)
  → Go LLM Gateway / Eino (provider、超时、schema)
  → OpenAI-compatible multimodal endpoint
  ← typed response {kind, candidates[], notes, usage}
  ← domain validation + persistence
  • API Key 只进入 Gateway 容器环境变量，不返回浏览器、不写 artifact。
  • 请求明确图像索引、原图/辅助图/参考图角色、完整类别目录与输出 JSON schema；参考 metadata 按不可信数据处理。
  • Go 适配器允许 1–8 张图片，Python 根据 query 视图数限制参考图，避免 prompt 索引与实际上传顺序错位。
  • 解析后再次按目录过滤、去重、补足候选；模型自由文本不能成为数据库指令。
  • 远程“是否完成未知”与明确失败分开处理，未知请求不盲目重发，避免重复计费与重复副作用。

3.15 前端架构与安全边界

前端使用 React、Vite 和 React Router，按用户工作流组织页面，而不是按数据库表生成后台。列表统一使用分页、搜索和领域状态筛选；数据集下拉等大数据选择器采用搜索 + 分页；训练参数根据预训练策略条件展示；模型注册表使用“数据集 → 数据集版本 → 模型”的二级范围，比较按钮只对合法组合启用。

当前系统面向可信本地开发，不声称已经完成公网生产安全。对外部署仍需要 OIDC/RBAC、租户级对象前缀、审计身份、速率限制、CSRF/CORS 策略、上传病毒/内容扫描、集中密钥管理和备份恢复演练。文档把这一点作为边界，不用“内部 token”替代真实身份系统。
