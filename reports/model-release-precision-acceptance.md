# 数据集级模型发布与精度导出

## 实现范围

- 注册表显示数据集名称、训练数据快照编号、训练任务名与发布版本；行尾提供详情、发布操作。
- 发布弹窗选择 FP32 / FP16，填写审计说明，展示后端预计版本与递增原因。只有成功完成导出、数值验证、MinIO 上传、SHA256/大小验证和数据库事务，才会开放新增部署文件。
- 默认 FP32。完整图像模型合并 LoRA 后输出完整 PT / ONNX；历史线性头仍输出分类头，不伪装成完整图像模型。
- 推理模型选项显示任务名、发布版本、Accuracy 与已导出的精度。本次不新增原先缺失的公共 HTTP 推理执行路由；导出文件运行验证与浏览器推理整条业务链验收是两件事。

## 版本规则

版本范围是稳定的数据集身份，数据库按 datasets 主键加行锁后分配。首次版本化发布为 v1.0.0。

1. 模型架构、骨干预训练标识 / SHA、分类头类型、池化 / 输入尺寸或训练策略（含 LoRA 开关和 rank）变化：MAJOR + 1，清零后两位。
2. 模型方案不变而训练数据快照变化：MINOR + 1，清零 PATCH。
3. 相同方案、相同快照重新训练发布：PATCH + 1，不要求指标必须提升。

比较基准是该数据集最后分配版本号的模型，包含已归档版本。多个变化同时存在时，MAJOR 优先。修改名称、说明、epoch 和优化器参数不触发 MAJOR。

FP32 / FP16 为同一发布版本的独立部署文件，补发不变更版本号、原文件不覆盖。重复请求已发布精度返回原结果。并发完成受模型更新时间 CAS 与数据集版本唯一约束保护，过期回调不能覆盖新状态。

历史已发布模型不自动回填猜测版本号；显示“历史发布”。首次显式使用新发布流程时分配版本号。UI 预览不是预留号码，最终以发布事务提交结果为准。

## 数值合同

FP16 ONNX 内部半精度，保留转换器所需的 FP32 算子，输入输出继续为 float32。并非强制所有节点都为 FP16，也不承诺在所有设备上更快。

- 输入：完整模型 float32[N,3,H,W]，按元数据执行 RGB 预处理；历史头 float32[N,feature_dim]。
- 输出：未归一化 logits。固定空间尺寸、动态 batch。
- PT 浮点权重随所选精度保存，非浮点 buffer 保持原类型；拒绝转换后非有限参数。
- ONNX 完成拓扑排序、checker、CPUExecutionProvider 实际推理与原模型对齐验证。
- FP32 rtol=1e-3 / atol=1e-4；FP16 rtol=1e-2 / atol=1e-2。非有限输出直接拒绝。
- 发布文件各自记录 precision、验证信息、SHA256、大小、模型 ID 与数据/训练血缘。

## 验收

- Go 全量单元测试、go vet；版本分配和并发用 race detector 验证。
- PostgreSQL 集成测试：同数据集不同模型并发发布号唯一且序号连续，过期完成回调拒绝。
- Python：真实 ViT-S 四种训练配置（DINO 冻结 / LoRA r8 / r16、ImageNet 全量）分别导出 FP32 与 FP16；随机 batch 和真实图片数值对比通过。训练仅 1 epoch，不作为模型质量评估。
- HTTP + Python gRPC + 独立 PostgreSQL 测试库 + MinIO：完整 ViT-S 与历史分类头两条发布链通过，补发 FP16 不改变版本，重复请求不新增文件记录，非法精度和损坏源文件拒绝发布。
- 前端 build、phase2-client、inference-client 与推理标签 smoke 通过。
- 浏览器实际页面：数据集名称/训练任务名、固定右侧详情/发布按钮、v1.0.0 预览、FP32 默认选择、FP16 切换、发布说明必填以及取消操作通过。未点击确认发布用户模型。
