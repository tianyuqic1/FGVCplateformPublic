## 验证范围

- Agent 与控制面 Go 单元、race 和 vet；公开工具、身份、CLI、Gateway 与业务集成契约。
- 真实 PostgreSQL 验证 20 用户 / 40 个 Run / 两组 Runner 的共享准入、请求去重、并发确认、租约恢复与旧 Runner fencing。
- 真实 PostgreSQL 与制品验证错分报告关联、SHA 校验、未完成训练和损坏报告拒绝。
- Python 验证 test/val 隔离、样本对齐、指标、空测试集、示例裁剪及训练写入路径；GPU 门控用例不计作已测。
- 前端静态检查、构建与受控浏览器测试，覆盖历史、确认、抽屉、错分入口和不自动发送。
- 真实模型完成只读查询、小样本训练唯一提交、成功跟踪与错分分析；仅验证流程，不代表模型质量或生产 GPU 容量。

2026-10-25 真实错分验收使用 3 个独立 test 样本、2 个错分，accuracy 0.3333、macro-F1 0.1667；模型回答明确区别历史混合指标，旧混合报告返回 unavailable。详情和可重现命令见 [错分分析](test-error-analysis.md#验证)。

## 部署与回退

1. 保留当前数据库与 volume 备份，等待实际训练任务完成后更新相应 Worker。
2. 用 `agent/deploy/init_local.py` 补齐本地新配置，应用平台 Alembic 迁移。
3. 更新控制面、Gateway、Agent 与前端；Agent 启动时应用自己的 SQL 迁移。
4. 更新训练 Worker，之后新训练保存独立 test 证据；旧训练不会自动重训。
5. 登录验证只读查询和方案展示，再以专用小数据版本显式验证写流程。

回退时停止 Agent 新增执行，保留其数据库与 volume。已提交的业务训练由平台继续管理，不随 Agent 回退撤销。数据库增量迁移不自动删表或回滚。
